An event is a change or action received from an app, such as a candidate being created or updated. Automations use events to decide when to start.

## Find an event

1. Select **Events** in the main navigation.
2. Search or filter the list to find the event.
3. Select the event row to open its details.

## Inspect event data

The **Data** tab shows the payload HireData received. Switch between its views to inspect the fields in the format that is most useful to you. Select the code view (`<>`) to see the raw JSON request body.

The event details also identify its app, trigger, locale, date, request information, and headers. Use these details when investigating why an automation did not start.

## Review related runs

Select the **Runs** tab to see the automations and runs associated with the event. Open a run to review its timeline and individual steps.

If no run appears, compare the event data with the automation's app, trigger, and Start conditions. See [Why Didn't My Automation Run?](/knowledge-base/why-didnt-my-automation-run) for a complete checklist.

## Replay an event

Replay sends the stored event through the current automation configuration again. This is useful after you fix a trigger or condition.

1. Open the event.
2. Select **Replay**.
3. Review the new entry on the **Runs** tab.

<Warning>
  Replay can repeat messages, record updates, tasks, and other actions that already completed. Inspect the earlier run before replaying an event.
</Warning>

If the replay does not produce the expected run, confirm that the automation is active and review the event's raw JSON for missing or differently formatted values.
