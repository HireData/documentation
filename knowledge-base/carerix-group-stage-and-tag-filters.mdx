Start with one Carerix record that should pass the filter and one that should fail. Check where the value is stored. A group on a person, a group of match stages, and an application tag call for different filters.

| What you mean in Carerix | Where to look in HireData | How to filter |
| --- | --- | --- |
| A group assigned to a candidate or contact | The groups field on the corresponding candidate or contact object | Select that field and inspect its available membership operators and values. Verify with records that belong to more than one group. |
| A stage group such as “Intake” that contains several match stages | **Stage** on the **Match** object | If the stage group itself is unavailable, use **Stage → one of** and select every individual stage in that group. Update the selection if the group changes in Carerix. |
| Tags attached to the application | **Match: Apply Tags** | Check the operators offered for this field. If you only see **is empty** and **is not empty**, you can test whether any tag exists. That field cannot select a particular tag with those operators. |

## Example: exclude members of either of two groups

Suppose you want to exclude members of Group A and Group B. A record should pass only if it belongs to **neither**. If the field offers a membership exclusion for a single group, combine “does not contain A” and “does not contain B” with **AND**. With **OR**, an A-only member passes the second condition.

Check four cases before sending: A only, B only, both, and neither. Only the last should pass. Inspect the values the Filter actually evaluated. If the picker lacks a suitable membership operator or the results differ, hold the bulk send and give support the object, field, operator and example record IDs.
