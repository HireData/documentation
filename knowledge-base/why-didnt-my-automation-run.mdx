_When an automation doesn't do what you expected, the cause is usually one of four things: the event never arrived, the automation isn't active, the event didn't pass your filters, or a run started but was cancelled. Work through the checks below in order — each one narrows down where the problem is. Step 5 covers how to replay the event once you've fixed the cause._

## 1. Did the event arrive?

Automations are triggered by events sent from your connected app. If no event arrived, nothing downstream can happen.

Go to **Events** and filter by the app you expect the event from. If you can find the event, open it and check the **Processes** tab — this lists the automations the event triggered and the runs it created, along with each run's status.

- **No event at all** – the problem is upstream, in the connection rather than the automation. For Carerix, see [Why is my Carerix not syncing with HireData](/apps/carerix/why-is-my-carerix-not-syncing-with-hiredata).
- **Event arrived, no processes listed** – the event likely didn't meet the criteria of any active automation. Continue to steps 2 and 3.
- **Event arrived, a run was created** – skip to step 4.

See [Events](/settings/logs/events) for how to read the event detail view.

## 4. Was a run created, and was it cancelled?

If a run exists but didn't finish, its status tells you why. Go to **Runs** and filter by state or sub-state, or reach the run from the **Processes** tab of the event. See [Runs](/settings/logs/runs) for how to read a run's detail view.

The cancellation reasons documented so far all relate to safety limits, which exist to prevent an automation from overwhelming the same contact.

### Run Cancelled – Send Limits Exceeded

The recipient has reached one of the limits configured in the **Safety Limits** section:

- **Email send limits** cap how many emails a single email address can receive.
- **Conversation send limits** cap how many conversations are initiated per phone number.

**_What to do:_** _Go to the Safety Limits section in HireData to review the current caps and adjust them to fit your outreach strategy. See [Automation Safety Limits](/settings/automation-safety-limits) for a breakdown of each limit and what it controls._

### Run Cancelled – Send Limits Per Automation Exceeded

The recipient has reached a limit set on that **specific automation**, rather than one of the limits above. Every automation in HireData can carry its own:

- **Email Limit** – how many emails this automation may send to the same email address within the selected time frame.
- **Conversation Limit** – how many new conversation attempts this automation may start for the same recipient within a given period. This applies to automations that initiate conversations via WhatsApp.

**_What to do:_** _Open the automation, click the three vertical dots in the upper right, and choose Settings to review its limits. See [Automation Safety Limits](/settings/automation-safety-limits) for the full breakdown._

<Warning>
  At the bottom of an individual automation's Safety Limits panel you'll find **Ignore Safety Limits**. When enabled, that automation bypasses all safety limits, both its own and the account-level ones. Only use this when you're confident the automation cannot trigger excessively, the recipients expect multiple messages, and your use case genuinely requires unrestricted sending. For most automations we strongly recommend keeping the safety limits enabled.
</Warning>

### Run Cancelled – Invalid Sender Email

The run was about to send an email, but HireData couldn't resolve a valid sending address for it, so the run was cancelled instead of sending from an address that would be rejected.

**In most cases the sending domain simply isn't verified.** A domain has to be verified in HireData before anything can be sent from it — if it isn't, emails from addresses on that domain can't be sent, and a run that tries to do so is cancelled with this reason.

**_What to do:_**

<Steps>
  <Step title="Check the domain's status">
    Go to **Settings → Domains** and find the domain that the sender address belongs to. If it isn't showing as verified, that's your cause.
  </Step>
  <Step title="Verify the domain">
    Add the generated DNS records at your domain provider, then click **Verify DNS** in HireData. See [How to Verify a Domain in HireData to Send Emails](/settings/domains/how-to-verify-a-domain-in-hiredata-to-send-emails) for the full walkthrough. The Email app must be installed before DNS records can be generated — if **Verify DNS** returns a 404 or does nothing, see [Why Can't I Verify My DNS Records?](/knowledge-base/why-cant-i-verify-my-dns-records)
  </Step>
  <Step title="Replay the event">
    Once the domain is verified, replay the original event to re-trigger the automation. See step 5 below.
  </Step>
</Steps>

If the domain is already verified, two other things are worth checking:

- **No Default Sender Email on the domain.** Each domain carries a **Default Sender Email**, used when the sender address isn't available in the event record received from your app. See [Adding a default sender to your domains](/settings/domains/adding-a-default-sender-to-your-domains).
- **The sender resolved from the event is empty or malformed.** Open the run and check the **Fields** tab to see the data the run actually used, and compare it against the original event via the **Related** tab. See [Runs](/settings/logs/runs).

## 5. Replaying the event once it's fixed

Once you've corrected the cause, you don't need to wait for the same thing to happen again — you can replay the original event to re-trigger the automation.

<Warning>
  When you replay an event, it can trigger runs across multiple automations at once. Before replaying, always check which automations and runs will be affected, especially if any of them include sending an email or a message. Replaying those without checking first could result in duplicate messages being sent to candidates or contacts.
</Warning>

Open the event, use the three-dot menu and select **Replay**. Before confirming, check which automations were triggered last time and whether any include **Send Email/Message/Survey** tasks.

Replaying behaves differently by automation type: event-based automations re-trigger immediately, while scheduled (one-time) automations keep their planned run date and only re-evaluate whether the event matches their conditions.

See [Events](/settings/logs/events) for the full replay walkthrough, including how to replay several events at once.
