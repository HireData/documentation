_Wenn HireData einen Run abbricht, protokolliert der abgebrochene Schritt eine Nachricht, die erklärt, warum er nicht fortgesetzt werden konnte. Diese Anleitung zeigt Ihnen, wo Sie diese Nachricht finden, was die häufigsten Abbruchgründe bedeuten und welche Einstellungen Sie überprüfen sollten, bevor Sie die Automatisierung erneut testen._

## Die Abbruchmeldung finden

Öffnen Sie zuerst den betroffenen Run, damit Sie mit der exakten Nachricht arbeiten können, statt zu raten, was die Automatisierung gestoppt hat.

1. Wählen Sie **Runs** in der Hauptnavigation.
2. Finden Sie den relevanten Run und wählen Sie seine Zeile.
3. Wählen Sie den abgebrochenen Schritt in der Timeline.
4. Öffnen Sie den Tab **Overview** und lesen Sie die Abbruchmeldung.

Sie können außerdem den Tab **Fields** verwenden, um die vom Schritt verwendeten Werte zu prüfen, und **Related**, um die Automatisierung oder das ursprüngliche Event zu öffnen.

## Häufige Abbruchgründe

| Meldung | Bedeutung | Wo prüfen |
| --- | --- | --- |
| `Invalid sender email.` | Der Send-Email-Schritt konnte seine konfigurierte Absenderadresse nicht verwenden. | Die Absenderadresse und deren Domain |
| `Send Limits Exceeded` | Der Empfänger hat ein E-Mail- oder Konversationslimit auf Kontoebene erreicht. | **Settings** \> **Safety Limits** |
| `Send Limits Per Automation Exceeded` | Der Empfänger hat ein für diese Automatisierung konfiguriertes Limit erreicht. | Die **Settings** der Automatisierung |

## Invalid sender email

Sie können `Invalid sender email.` sehen, wenn ein Send-Email-Schritt die konfigurierte Absenderadresse nicht verwenden kann. Eine bestätigte Ursache ist das Senden von einer Domain, die in HireData nicht verifiziert wurde.

### So beheben Sie das

1. Gehen Sie zu **Settings** \> **Domains**.
2. Finden und öffnen Sie die Domain, die von der Absenderadresse verwendet wird.
3. Wenn noch keine DNS-Einträge generiert wurden, wählen Sie **Generate DNS Records**.
4. Fügen Sie jeden generierten Eintrag exakt so, wie HireData ihn anzeigt, in die DNS-Einstellungen bei Ihrem Domain-Anbieter ein.
5. Kehren Sie in HireData zur Domain zurück und wählen Sie **Verify DNS**.
6. Sobald die Domain verifiziert ist, öffnen Sie die betroffene Automatisierung und wählen Sie den **Send Email**-Schritt.
7. Bestätigen Sie, dass das Absenderfeld die beabsichtigte E-Mail-Adresse enthält und deren Domain mit der verifizierten Domain übereinstimmt.
8. Speichern Sie jede Korrektur und testen Sie dann mit einem neuen Event oder spielen Sie das ursprüngliche Event vorsichtig erneut ab.

<Warning>
  Wenn HireData `DNS Verification Failed - Please add your DNS records to your domain.` anzeigt, konnten noch nicht alle erforderlichen Einträge gefunden werden. Bestätigen Sie, dass jeder generierte Eintrag beim Domain-Anbieter gespeichert wurde, prüfen Sie, ob der Anbieter im Feld **Host/Name** nur die Subdomain erwartet, und lassen Sie DNS-Änderungen ausreichend Zeit zur Verbreitung, bevor Sie erneut **Verify DNS** wählen.
</Warning>

Die vollständige DNS-Einrichtung inklusive anbieterspezifischer Formatierungstipps finden Sie unter [Eine Domain in HireData verifizieren, um E-Mails zu senden](/settings/domains/how-to-verify-a-domain-in-hiredata-to-send-emails).

Wenn **Verify DNS** stattdessen einen 404-Fehler oder keine Antwort zurückgibt, ist möglicherweise die Email-App nicht installiert. Folgen Sie [Warum kann ich meine DNS-Einträge nicht verifizieren?](/knowledge-base/why-cant-i-verify-my-dns-records).

Wenn die Domain verifiziert ist und die Absenderadresse korrekt erscheint, notieren Sie die Run-ID, den Automatisierungsnamen und die Absenderadresse, bevor Sie den HireData-Support kontaktieren.

## Send Limits Exceeded

Dieser Abbruch bedeutet, dass der Empfänger ein Sicherheitslimit auf Kontoebene erreicht hat. HireData stoppt den Schritt, um zu verhindern, dass dieselbe E-Mail-Adresse oder Telefonnummer mehr Nachrichten erhält, als Ihr Konto zulässt.

### So beheben Sie das

1. Gehen Sie zu **Settings** \> **Safety Limits**.
2. Prüfen Sie die Limits unter **Prevent Message Overload**.
3. Prüfen Sie, ob der Empfänger das relevante E-Mail- oder Konversationslimit erreicht hat.
4. Passen Sie das Limit nur an, wenn eine höhere Frequenz für Ihre Outreach-Strategie angemessen ist.

Eine vollständige Erklärung der Steuerelemente auf Kontoebene finden Sie unter [Automation Safety Limits](/settings/automation-safety-limits).

## Send Limits Per Automation Exceeded

Dieser Abbruch bedeutet, dass der Empfänger ein E-Mail- oder Konversationslimit erreicht hat, das speziell für die Automatisierung konfiguriert wurde. Andere Automatisierungen können unterschiedliche Limits haben.

### So beheben Sie das

1. Öffnen Sie die betroffene Automatisierung.
2. Öffnen Sie das Drei-Punkte-Menü und wählen Sie **Settings**.
3. Prüfen Sie die E-Mail- und Konversationslimits unter **Message limits**.
4. Bestätigen Sie, ob der Empfänger bereits die maximal zulässige Anzahl an Nachrichten innerhalb des konfigurierten Zeitraums erhalten hat.
5. Passen Sie das Limit nur an, wenn die beabsichtigte Nachrichtenfrequenz der Automatisierung dies erfordert.

<Warning>
  Die Option **Ignore all safety limits** entfernt sowohl automatisierungsspezifische als auch kontoweite Schutzmaßnahmen für diese Automatisierung. Verwenden Sie sie nur, nachdem Sie das Risiko doppelter oder übermäßiger Nachrichten geprüft haben.
</Warning>

## Nach einer Korrektur testen

Verwenden Sie nach einer Korrektur der Absender- oder Limit-Konfiguration wenn möglich ein neues Test-Event. Sie können auch das ursprüngliche Event erneut abspielen, prüfen Sie aber zuerst dessen früheren Run, um zu sehen, welche Schritte bereits abgeschlossen wurden.

<Warning>
  Das erneute Abspielen eines Events kann E-Mails, Nachrichten, Datensatz-Aktualisierungen, Aufgaben und andere Aktionen aus dem vorherigen Run wiederholen.
</Warning>

## Benötigen Sie weitere Hilfe?

Wenn die Abbruchmeldung hier nicht aufgeführt ist oder die vorgeschlagenen Prüfungen sie nicht beheben, kontaktieren Sie [support@hiredata.com](mailto:support@hiredata.com). Geben Sie an:

- Einen Link oder die ID des Runs
- Den Namen der Automatisierung
- Den abgebrochenen Schritt
- Die exakte Abbruchmeldung
- Alle relevanten Absender- oder Empfängerdetails
